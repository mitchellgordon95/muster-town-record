- **Secretary** (2026-11-15T20:57:25.756Z): A normal unit test checks one example you wrote by hand: "with these 3 goals and 2 buildings, building B's answerer is goal X." A property test instead states a law that must hold for every input, and a library (fast-check here) generates hundreds of random inputs and checks the law on each. When one fails, it shrinks the input to the smallest case that still breaks it and shows you that.

The live example is Mara's chain-of-command test (packages/core/test/chain-of-command.test.ts). Line 10-13 builds random towns: 1-25 goals in a random tree, random captains, up to 12 buildings. Each runs 100 random towns by default.

Why it's the alternative to Bend proofs: a proof says the law holds for all inputs; property tests say it held for every input they tried. Weaker in principle, but they run on the real TypeScript, not a hand-copied version, so they can't drift from the code that ships.
